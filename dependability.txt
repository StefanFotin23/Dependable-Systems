# Dependability Analysis of the Weather Warning System

This document outlines the architectural features contributing to the system's **Dependability** (Trustworthiness/Quality), distinguishing between Development (WSL/Kind) and Production environments.

## 1. Technology Stack
The project utilizes a Cloud Native stack to ensure robustness and manageability:

-   **Docker:** Container runtime for consistent execution.
-   **Kubernetes (Kind):** Container orchestration, self-healing, and management.
-   **Ansible:** Infrastructure as Code (IaC) for automated, reproducible provisioning.
-   **Helm:** Package manager for deploying complex K8s apps (Prometheus, Loki).
-   **Node-RED:** Core event-driven application logic.
-   **NGINX Ingress:** Traffic routing and load balancing.
-   **Cert-Manager:** Automated TLS/SSL certificate management.
-   **Longhorn (Prod):** Distributed block storage engine that **synchronously replicates volumes** across multiple nodes. Used only in Production to prevent data loss if a node fails; disabled in Dev to save resources on the single-node cluster.
        Longhorn requires the host machine (the Kubernetes node) to have an iSCSI initiator installed (open-iscsi)    
-   **MinIO:** S3-compatible object storage for data backups.
-   **Velero (Prod):** Disaster recovery tool that takes **full cluster snapshots** (ETCD state + Persistent Volumes) to object storage. Reserved for Production to protect against catastrophic cluster failures.
        Velero works best when paired with Longhorn.
-   **Prometheus:** Metrics collection and alerting.
-   **Loki:** Centralized log aggregation.
-   **Grafana:** Unified visualization dashboards.
-   **Ngrok (Dev):** Secure tunneling for external access.

## 2. Architectural Vision
-   **Containerization:** Ensures consistency across all environments.
-   **Orchestration:** K8s provides the foundation for automation and resilience.
-   **IaC:** Ansible eliminates manual errors and ensures the infrastructure is self-documenting.

## 3. Availability (Uptime)
Ensures the system remains operational and accessible.
-   **Self-Healing (K8s):** Automatically restarts failed pods on healthy nodes.
-   **Disruption Protection:** `PodDisruptionBudget` (`minAvailable: 1`) prevents voluntary downtime during maintenance.
-   **Failure Isolation:** `podAntiAffinity` ensures future replicas are distributed across different nodes.
-   **Storage Resilience (Prod):** **Longhorn** replicates volumes across nodes. If a node fails, the volume reattaches elsewhere instantly.

## 4. Reliability & Data Durability
Focuses on data integrity and persistence.
-   **Persistent Storage:** `PersistentVolumeClaim` (PVC) decouples data lifecycle from the pod.
-   **Data Redundancy (Prod):** **Longhorn** maintains multiple synchronous replicas of data.
-   **Automated Backups (App-Level):** A **fully automated** process via Ansible and a Kubernetes **CronJob** runs **hourly**, archiving Node-RED data to a dedicated **S3 bucket (`project-data-backup`)** in **MinIO** for off-site redundancy (low RPO).
-   **Cluster Disaster Recovery (Prod):** **Velero** provides full cluster snapshots.

## 5. Scalability Strategy
The system is built on scalable primitives but deliberately configured for stability.
-   **Horizontal Pod Autoscaling (HPA):**
    -   *Status:* Not enabled.
    -   *Reason:* The "RSS Feed Processor" logic is stateful (in-memory context) and relies on interval triggers. Multiple replicas would cause **duplicate execution** (redundant API calls/alerts) and **state fragmentation** (inconsistent UI).
    -   *Capability:* The architecture supports HPA (requires resource limits), but **Vertical Scaling** (more CPU/RAM) is preferred for this workload due to Node.js's efficient non-blocking I/O.
-   **Load Balancing:** **NGINX Ingress** is ready to distribute traffic across multiple replicas if the architecture evolves.

## 6. Maintainability & Observability
-   **Simplified Operations:** A `Makefile` abstracts complex commands (`make setup`, `make update`).
-   **Automated Infrastructure:** Includes idempotent Ansible tasks for syncing S3 credentials and a Kubernetes Job for **automatic MinIO bucket provisioning**.
-   **Decoupled Configuration:** `ConfigMaps` and `Secrets` allow updates without rebuilding images.
-   **Observability Stack:**
    -   **Prometheus:** Monitors resource usage (CPU, RAM).
    -   **Loki:** Aggregates logs for troubleshooting.
    -   **Grafana:** Visualizes metrics and logs in real-time.

## Conclusion
By integrating Kubernetes orchestration, replicated storage, automated backups, and comprehensive observability, the system achieves a robust balance of **Availability, Reliability, and Recoverability**. The deliberate decision to enforce a singleton pattern (`replicas: 1`) prioritizes data consistency and operational simplicity.
